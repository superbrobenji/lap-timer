# Plan 04: Host-Rendered UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. Sessions 4.2–4.3 are appended to this document at the start of each session (like plans 02/03), once the code they build on exists.

**Goal:** Build the lap-timer's screen UI as a pure-C, host-testable framebuffer renderer plus the moto screens and menu, driven by a `screen_model_t`, with every screen captured as a committed PBM golden — all before any physical e-paper panel exists.

**Architecture:** `components/core/ui/` stays pure C11 (no ESP-IDF/FreeRTOS/malloc), like the rest of `core`. `render.c` owns a 1-bpp landscape framebuffer and the drawing primitives; `fonts.c` (generated by `tools/fonts/gen_fonts.py`) holds three bitmap fonts; `screens_moto.c` renders each screen as a pure function of a `screen_model_t`; a menu model drives navigation. Rendering is deterministic and side-effect-free, so host tests render every screen from a fixed model and compare the framebuffer to a committed `test/snapshots/<screen>.pbm` golden. The firmware-side `ui` task (`components/app/ui/`, session 4.3) consumes events into the model and calls the renderer, but drives no display yet (there is no panel; it logs the dirty rectangle instead of refreshing). The display driver (`display_epaper_ssd1680`) and the `disp_refresh` glue land in a later plan when the panel arrives.

**Tech Stack:** C11, the existing host test harness (Unity, `test/CMakeLists.txt`, clang `test/build` + gcc-16 `test/build-gcc`), ESP-IDF v5.3.2 for the firmware-side `ui` task (session 4.3 only). `tools/fonts/gen_fonts.py` is a Python 3 maintenance tool (Pillow + the bundled DejaVu Sans Mono Bold TTF); it is run by hand to regenerate `fonts.c`, never in CI or the build.

**Spec:** `docs/superpowers/specs/2026-09-14-lap-timer-design.md` — §20.2 (framebuffer + renderer + fonts + icons), §20.4 (screen model), §20.5 (riding screens), §20.6 (one-shot screens), §20.7–20.8 (menu + buttons), §11.4 (drag benches), §4.8 (framebuffer 296×128/8 = 4.7 KB). Session 4.1 implements §20.2.

## Global Constraints

- **`components/core/ui/**` stays pure C11** — no ESP-IDF/FreeRTOS/driver header, no `malloc`/`free` after init, `-Wall -Wextra -Werror -Wshadow` (with `-Wconversion` non-fatal as elsewhere in core). The framebuffer and all screen state are static or caller-provided buffers.
- **The framebuffer is landscape, 1 bpp, `0 = black`**, `width/8 × height` bytes, origin top-left. Sized for the larger panel (296×128 → 4.7 KB); the 2.13" panel (250×122) is a render-time width/height, not a second buffer.
- **Rendering is a pure function of the model.** No time, no I/O, no globals mutated outside the passed framebuffer/model. This is what makes the PBM goldens deterministic.
- **Generated `fonts.c` is committed** and is the build input; `gen_fonts.py` + the bundled TTF regenerate it as a manual maintenance action (never in CI). `grep`-clean whitespace; the TTF and its license live under `tools/fonts/`.
- **PBM goldens are committed** under `test/snapshots/`; they are `.pbm` binary (P4) marked `binary` in `.gitattributes`. A test regenerates the framebuffer and compares byte-exact to the golden (no libm/transcendental in the renderer, so byte-exact is portable across clang/gcc, unlike the §22.2 circuit fixtures).
- **No display driver in plan 04.** The `ui` task (4.3) renders into the framebuffer and logs the dirty box; it never calls a panel. `moto_neo6m` must still build and boot with the `ui` task present.
- **Subagent models:** never dispatch a subagent on Fable; haiku/sonnet/opus by task tier.

## Session 4.1 — framebuffer renderer, fonts, and PBM snapshots (§20.2)

Roadmap exit: `test_ui` renders text at the three sizes into `test/snapshots/*.pbm`; tag `p04-d1`. SERIAL (2 tasks). Ruling: `gen_fonts.py` needs Pillow (`pip install pillow`) and a DejaVu Sans Mono Bold TTF; bundle the TTF under `tools/fonts/` (DejaVu is redistributable under the Bitstream Vera / DejaVu license — include the license text) so regeneration is reproducible. The generated `fonts.c` is committed and is the only font input the build/tests use, so Pillow is NOT a build or CI dependency. The framebuffer uses NO floating point or libm, so the PBM goldens are byte-exact and portable (clang and gcc-16 must both produce identical snapshots) — unlike the §22.2 circuit fixtures which needed a tolerant compare.

### Task 1: font format + `gen_fonts.py` + generated `fonts.c`

**Files:** create `components/core/ui/include/core/ui/fonts.h`, `components/core/ui/fonts.c` (generated), `tools/fonts/gen_fonts.py`, `tools/fonts/DejaVuSansMono-Bold.ttf` (+ license), `components/core/ui/icons.c` (icon bitmaps). Modify `components/core/CMakeLists.txt` (add `ui/` sources + include dir) and `test/CMakeLists.txt` as needed.

**Interfaces produced (`fonts.h`):**
```c
typedef struct {
    uint8_t  w, h;            /* glyph cell size in px (fixed advance = w) */
    uint8_t  first, count;    /* first ASCII code, number of glyphs */
    uint8_t  stride;          /* bytes per glyph row = (w + 7) / 8 */
    const uint8_t *bitmaps;   /* count * h * stride bytes, 1bpp, MSB-first, row-major */
} font_t;
extern const font_t FONT_BIG;    /* 40 px: glyphs "0-9 : . - + S" */
extern const font_t FONT_MED;    /* 24 px: "0-9 : . - + A-Z" */
extern const font_t FONT_SMALL;  /* 12 px: ASCII 32..126 */
/* Non-contiguous glyph sets (BIG/MED) are stored densely; render maps a char to its glyph index
 * via a per-font lookup emitted by gen_fonts.py, returning a blank cell for an unmapped char. */
```

- [ ] **Step 1** — write `gen_fonts.py`: load the bundled TTF with Pillow `ImageFont.truetype(path, px)`, rasterise each glyph in the font's set to a 1-bpp cell of the font's fixed advance (monospace → uniform cell width), threshold at 50 %, emit `fonts.c` with the `font_t` tables + the per-font char→index map. Deterministic (fixed px, fixed threshold, fixed TTF).
- [ ] **Step 2** — run it: `pip install pillow` (host tool only), `python3 tools/fonts/gen_fonts.py > components/core/ui/fonts.c`; commit the generated `fonts.c` and the TTF+license. Record the Pillow version + command in a header comment of `fonts.c`.
- [ ] **Step 3** — `icons.c`: the ten 12×12 1-bpp icons (§20.2: GPS, GPS-strike, IMU-q, disk, disk-full, disk-warn, battery-low, thermometer, BLE, SAFE), hand-authored bitmaps, exposed as an `icon_t`/table `fb_icon` indexes.
- [ ] **Step 4** — wire `components/core/CMakeLists.txt` to compile `ui/render.c`, `ui/fonts.c`, `ui/icons.c` and expose `include/`. Build the host test tree to confirm `fonts.c` compiles.
- [ ] **Step 5** — commit (`feat(ui): bitmap fonts (gen_fonts.py + generated fonts.c) and icons (§20.2)`).

### Task 2: framebuffer primitives + PBM writer + `test_ui`

**Files:** create `components/core/ui/include/core/ui/render.h`, `components/core/ui/render.c`, `test/pbm.h`, `test/pbm.c`, `test/test_ui.c`, `test/snapshots/*.pbm`. Modify `test/CMakeLists.txt` (register `test_ui`, link the ui sources).

**Interfaces produced (`render.h`):**
```c
typedef struct { uint16_t x0, y0, x1, y1; bool valid; } fb_rect_t;   /* dirty box, half-open */
typedef struct {
    uint8_t  *bits;           /* caller-owned, (w/8)*h bytes; 0 = black */
    uint16_t  w, h, stride;   /* stride = w/8 */
    fb_rect_t dirty;          /* accumulated bounding box of all draws since fb_clear */
} fb_t;
void fb_init(fb_t *fb, uint8_t *bits, uint16_t w, uint16_t h);   /* w must be a multiple of 8 */
void fb_clear(fb_t *fb, uint8_t black);                           /* fills + resets dirty to whole frame */
void fb_rect(fb_t *fb, int x, int y, int w, int h, uint8_t black, bool fill);
void fb_hline(fb_t *fb, int x, int y, int w, uint8_t black);
int  fb_text(fb_t *fb, const font_t *f, int x, int y, const char *s);        /* returns pen-x after the string */
int  fb_text_right(fb_t *fb, const font_t *f, int x_right, int y, const char *s);  /* right edge at x_right */
void fb_icon(fb_t *fb, uint8_t icon_id, int x, int y);
void fb_bar(fb_t *fb, int x, int y, int w, int h, uint8_t pct);   /* outlined bar, pct 0..100 filled */
```

- [ ] **Step 1** — write the failing `test_ui` first: init a 296×128 `fb_t` over a static buffer, `fb_clear` white, `fb_text(FONT_BIG, ...)` a lap-time string, `fb_text(FONT_MED,...)`, `fb_text(FONT_SMALL,...)`, an icon and a bar; write the framebuffer to `test/snapshots/text_big.pbm` etc. via `pbm_write`; assert `pbm_eq_file` against the committed golden. Run it: FAIL (no render.c / no golden yet).
- [ ] **Step 2** — implement `render.c`: the framebuffer set/clear/rect/hline; `fb_text`/`fb_text_right` walking the string, mapping each char to its glyph, blitting the 1-bpp cell with clipping; `fb_icon`; `fb_bar`; every primitive extends `fb->dirty`. - [ ] **Step 3** — `pbm.c`: `pbm_write(path, fb)` emits a P4 (binary) PBM (1 = black to match PBM convention; document the mapping vs the fb's 0=black); `pbm_eq_file(path, fb)` compares byte-exact and, on mismatch, writes `<path>.actual.pbm` for inspection.
