# Lap Timer Implementation Roadmap

**Spec:** `docs/superpowers/specs/2026-09-14-lap-timer-design.md`
**Date:** 2026-09-14

The roadmap orders work by hardware availability. Everything that can be built and tested on the host or on the bare ESP32 dev board comes first. Each numbered plan is a separate implementation plan document in this directory, written when its predecessor is complete so it can reference the real code.

## Hardware windows

| Window | Expected | Hardware in hand | Unlocks |
|--------|----------|------------------|---------|
| A | now | ESP32 DevKit V1 (CH340) only. No battery, no GPS, no IMU, no display. | Host-side core, firmware skeleton with simulated sensors, BLE/serial export, OTA, UI rendered to images |
| B | +1 week | TP4056, 2× 18650, holder | Power path, battery sensing, sleep states, current measurement |
| C | +1 month | GY-NEO6M v2, MPU6050 (GY-521) | Real sensor drivers, calibration, first track session |
| D | not yet ordered | SSD1680 e-paper panel (2.9" V2 recommended) | Display driver, on-device UI |

## Sequencing

```
Window A:  1 → 2 → 3 → 4 → 5
Window B:  6                (as soon as battery parts + regulator arrive; 3 must be done)
Window D:  7                (as soon as a panel arrives; 4 must be done)
Window C:  8 → 9            (GPS + IMU arrive; 3 and 6 must be done)
```

Plans 4 and 5 can be swapped or interleaved; both need only the dev board. If the panel arrives before the battery, do 7 before 6.

## Definition of done per plan

- All plan tasks checked off, tests green on host (`ctest`) and, for firmware plans, the bench procedure in the plan executed with results noted in the plan file.
- Spec deviations discovered during implementation are written back into the spec in the same commit.
- Each plan ends with a tagged commit `plan-NN-done`.
