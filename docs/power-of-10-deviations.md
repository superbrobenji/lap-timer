# Power of 10 deviation register

Design authority: `docs/superpowers/specs/2026-09-17-power-of-10-compliance-design.md` §2 (the
adversarial deviation model) and §4 (this table's format). Plan:
`docs/superpowers/plans/2026-09-17-plan-4.5-power-of-10.md`.

Every row here survived the §2 burden of proof: a spelled-out compliant alternative was
considered and concretely shown to fail (infeasible, or not worth its cost) before the site was
accepted as a deviation. "It's how it's written now" or "it's convenient" are never sufficient
justification on their own. `tools/lint/power_of_10.py` reads this table and skips a listed
`file:symbol` site for the matching rule; every other site is a finding.

Rows PD-1..PD-6 are the genuinely-unavoidable IDF/FreeRTOS API boundary sites (design §3 rule 9's
first bucket): the FreeRTOS/IDF function signature itself is a function pointer, and there is no
way to call that API at all without supplying one short of not using the SDK.

Session 4.5.5 reworked the codebase's OWN callbacks (design §3 rule 9's second bucket) rather than
registering them: the lap/drag engine event emit → caller-drained event buffers; the `ses` reader
→ a pull iterator; `sto_list` → a pull iterator; `core_set_assert_hook` → a link-time
`core_assert_report`; the board button ISR → a direct queue post (and the dead PPS callback was
deleted). One internal callback SURVIVED that rework and is registered below as PD-7: `cmd_emit`.
Under Holzmann's *refined* rule 9 — which this project adopted (design §3 rule 9) and which permits
a function pointer "so long as it is always tractable which function or functions are actually
pointed to" — `cmd_emit` qualifies: it is a transient per-call parameter (never stored), passed at
exactly three call sites, all in `export_serial.c`, to two named static functions. The compliant
reworks were considered and rejected (see PD-7), so it is accepted, not removed.

Rule 9 (`--enforce-fnptr`) becomes a blocking CI check in Session 4.5.6; with the 4.5.5 rework
complete, `--enforce-fnptr` reports zero unregistered `(*name)(` sites tree-wide.

| PD-7 | 9 | components/app/include/app/cmd.h:cmd_emit_fn | (a) A link-time `extern int cmd_emit(void *ctx, ...)` that `export_serial` defines (like `core_assert_report`), dispatching the single-shot vs streamed transport on a `ctx` kind field. | PD-8 | 9 | components/app/link/link.c:link_task | Don't create the peer-stream drain as its own pinned FreeRTOS task (fold its work into an existing task's loop, or hand-roll cooperative scheduling). | Same IDF API-contract reason as PD-1..4: `xTaskCreateStaticPinnedToCore`'s `pxTaskCode` parameter (`TaskFunction_t`) is a function pointer by the FreeRTOS/IDF contract, and there is no way to obtain a statically-allocated pinned task without it.
